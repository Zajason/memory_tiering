# Workload sources and input preparation

The local GAPBS checkout is revision
`2972aeb2703165bafd921222f4ed7196f542d3a8`, with the repository ROI-marker patch.
Its equivalence to the authors' exact build is unconfirmed. Setup scripts fetch
sources and large files into ignored workload/storage directories.

For the 27 October fidelity campaign:

- `fetch_twitter.py DIRECTORY` fetches the four official KAIST Twitter gzip
  chunks and verifies size, gzip integrity and SHA256 provenance.
- `prepare_twitter.cpp` reads their concatenated byte stream, verifies the
  published 41,652,230 nodes and 1,468,365,182 directed edges, and makes two
  deterministic induced reductions using SplitMix64 vertex selection. The
  small fixture test deliberately splits an edge across archive boundaries.
  A self-loop sentinel preserves trailing selected isolated vertices; GAPBS
  removes the sentinel while retaining the declared vertex count. The fixture
  also checks the resulting CSR against the actual GAPBS converter when present.
- `prepare_fidelity_inputs.py --out MANIFEST.json` uses the research HDD,
  builds undirected CSR with GAPBS, prepares published Google+ snapshots 4 and 2,
  and records native one-thread/one-trial peak RSS separately from Pin overhead.
- `prepare_gplus.py` removes TimeID after selecting a published snapshot.
  TimeID is never an SSSP distance. SSSP weights are generated by GAPBS.

Our reductions and weight choices are recorded in `inputs.json`. The authors'
reduced Twitter files and Google+ weighted files remain unavailable. Input size,
vertex ordering, selection, graph direction, edge weights and benchmark settings
all matter; a matching file size alone does not establish equivalent inputs.
